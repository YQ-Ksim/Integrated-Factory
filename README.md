# 工厂线路集成系统

目标环境：Minecraft Java 1.21.1、NeoForge 21.1.209、Create 6.0.10。

当前发布文件：[integrated_factory-2.4.4.jar](releases/integrated_factory-2.4.4.jar)

## 2.4.4 传动杆截面贴图修正

- 修正半像素延伸传动杆的模型面映射：四个轴体侧面使用 Create 官方 `axis` 贴图，上下两个真正的轴端使用 `axis_top` 截面贴图。
- 保留两端各延伸 0.5 像素的几何，避免轴体与离合器/齿轮箱机身边界重叠。

## 2.4.3 半像素延伸传动杆

- 保留上一版的 PCL2 元数据、图标和双元数据文件。
- 恢复集成核心与简单集成单元传动杆两端各延伸 0.5 像素的几何，避免与机身边界重叠。
- 自定义 partial 继续使用 Create 官方 `axis` 轴体侧面和 `axis_top` 截面贴图。

## 2.4.0 合成配方

- 新增集成单元、输入端口、输出端口、简单集成单元、拓展接口和应力端口配方。
- 集成单元与应力端口使用钻石、黑曜石、铁块，并分别消耗 Create 传动杆和应力表。
- 输入/输出端口分别使用铜锭/绿宝石；简单集成单元和拓展接口使用对应模组方块与 Create 传动杆。

## 2.3.8 主网络重载后负容量修复

- 应力端口计算主世界可用 SU 时只统计当前实际加载的动力源与核心以外的实际负载。
- 排除 Create 重载期间的 `unloadedStress` / `unloadedCapacity` 快照，避免桥接容量被错误压为 0。
- 修复远端应力表在假过载时显示为正常负载相反数的问题（`0 - 负载`）。

## 2.3.9 主网络残留过载标记修复

- 世界重载恢复窗口内检查主世界核心所在的 Create 网络。
- 仅当网络中的所有待恢复成员都已重新挂接时，清除残留的未加载快照并同步过载状态。
- 主网络仍有未加载的普通 Create 设备时保留其合法应力，不会误删其他设备的负载。

## 2.3.7 远端应力仅统计实际加载成员

- 远端应力端口不再直接使用包含 Create `unloadedStress` 快照的总量。
- 机器空间应力改为遍历当前 `KineticNetwork.members` 中仍对应实际方块实体的成员，排除不存在、未加载和旧存档残留设备。
- 主世界网络容量结算仍使用 Create 的完整网络数据，避免影响主世界其他区块的正常应力计算。

## 2.3.6 远端网络对象替换恢复

- 应力端口检测到 Create 远端 `KineticNetwork` 对象更换时，会对新网络再次清理未加载成员快照并强制同步。
- 覆盖机器空间成员延迟加载导致网络在恢复窗口中途重建的情况，避免旧应力在约一秒后重新出现。

## 2.3.5 强制同步 Create 过载状态

- 世界重载恢复时，在网络数值重算后显式调用 Create `KineticNetwork.sync()`，刷新所有成员的过载标志。
- 修复网络容量/负载数值已恢复但方块实体仍保留存档中的 `overStressed=true`，必须手动更新动力源才解除的问题。

## 2.3.4 核心先入网时的残留应力修复

- 记录恢复前核心原有的远端应力，在核心或应力端口先后入网的两种顺序下都能定位到这一个旧成员贡献。
- 核心重新入网时只扣除对应的 `unloadedStress` 残值，不清空主网络中其他正常未加载设备的应力。
- 主网核心与远端应力端口恢复使用同一套一次性恢复标记，避免恢复顺序不同造成假过载。

## 2.3.3 主网络核心负载恢复

- 恢复阶段不仅清空节点快照，也会立即把主世界核心在 Create 网络中的旧应力成员值更新为零并重算。
- 解决主网络仍保留旧核心负载、应力端口可用容量被压成零，必须手动更新动力源才能恢复的问题。

## 2.3.2 清理 Create 未加载成员残留应力

- 应力端口在房间区块完成加载后，清除 Create 网络保存的未加载成员应力、容量和成员数快照，再从当前机器成员重建网络。
- 结合区块重载恢复窗口，避免不存在的旧机器继续贡献应力，也避免重载后主网络持续显示过载。

## 2.3.1 机器空间区块重载应力恢复

- 应力端口每次区块实体重新加载时清除节点运行时应力/转速快照，防止旧的远端负载再次进入主世界网络。
- 应力端口等待 Create 完成恢复机器空间动力网络后再发布远端应力；恢复期间先按主网当前可用容量重新开放动力源。
- 继续使用当前网络成员计算应力，避免 Create 重载缓存中的残留负载导致假过载。

## 2.3.0 重载应力快照与残留负载修复

- 服务器启动时清空节点中仅用于运行时的远端应力和理论转速快照，避免旧快照在 Create 网络恢复前再次提交到主网。
- 应力桥接改为读取 Create 当前网络成员计算出的应力和容量，不再直接信任重载期间可能包含 `unloaded` 残留的缓存字段。
- 远端网络重建及主网重新登记时继续执行联合重算，修复重进世界后假过载和应力端口显示不存在负载的问题。

## 2.2.9 世界重载后应力网络恢复

- 核心、简单单元或应力端口重新接入 Create 动力网络时，触发一次网络应力与容量联合重算，清理 Create 保存的旧容量/负载快照。
- 远端负载快照改变时立即请求主维度核心所在网络重新登记并重算，避免必须手动更新动力源才能解除错误过载。
- 日常稳定运行仍按数据变化或网络实例更换触发，不逐 tick 全量扫描网络。

## 1.3.0 当前功能

- 注册集成单元、简单集成单元、拓展接口、输入端口、输出端口和应力端口，并加入创造模式物品栏。
- 节点 UUID、机器空间坐标和共享输入/输出各 27 格库存写入主世界 `SavedData`；库存由服务端作为唯一权威数据源。
- 输入/输出端口通过 NeoForge `ItemHandler` capability 提供方向性自动化：主维度输入端只插入、机器空间输入端只提取；输出端口相反。
- 大型结构按六面 BFS 识别，默认最多 128 个结构方块（可在服务器配置中调整），并要求单一核心；失联成员在核心重扫时解除库存绑定。
- 所有节点共用 `integrated_factory:factory_room` 隐藏维度，每个节点分配互相隔离的 10×10×10 房间。右键核心进入，执行 `/factory_return` 或 `/factory return` 返回，并恢复进入前的飞行权限。
- 返回位置与飞行状态同时存入玩家数据和世界 `SavedData`。若两处记录都不可用，返回命令会将玩家送到主世界出生点，避免滞留在机器空间。
- 潜行右键大型集成核心显示结构统计（输入端口、输出端口、拓展接口、核心数量）；潜行右键输入端口只打开对应的 27 格输入库存，输出端口只打开对应的 27 格输出库存。菜单标题标明库存类型。
- 潜行右键简单集成单元保持 54 格组合菜单，上方 27 格为输入库存、下方 27 格为输出库存，菜单标题分别标明上下区域。所有界面直接读写服务端共享库存。
- 机器空间内可使用 `/factory inventory` 打开库存、`/factory status` 查看节点状态、`/factory allow <玩家>` 授予协作权限、`/factory deny <玩家>` 撤销权限；节点所有者可管理协作者。
- 进入机器空间前会在房间内搜索无流体且与玩家碰撞箱不重叠的落点；没有可用落点时取消传送。越界回位也使用碰撞检查，找不到安全位置则执行返回命令的安全回退。
- 应力端口复用 Create 官方传动轴模型，并注册 Create 的 kinetic block entity renderer，让可见传动轴随动力网络转速旋转。核心与简单单元均以正面朝向为基准，左右两侧贯通动力轴；简单单元正面输入、背面输出。
- 应力端口按节点主维度核心的理论转速同步 Create 动力输出，读取远端 `KineticNetwork` 的应力总量；主维度核心按 `远端 SU / 主维度 RPM` 映射为 Create 应力影响。主维度核心停转或过载时，远端容量门控为零，同时保留远端理论负载用于结算。

### 新手使用

- 放置集成单元后，首次进入或打开该节点界面的玩家成为节点所有者。右键进入机器空间；潜行右键核心打开库存菜单。
- 在机器空间内放置 Create 机器和传动结构。输入端口从共享输入库存取料，输出端口向共享输出库存回存；主维度自动化输入端只接受物品，自动化输出端只允许提取。
- 所有者进入机器空间后执行 `/factory allow <在线玩家>` 添加协作者，使用 `/factory deny <在线玩家>` 撤权。协作者可进入、打开库存与查看状态，但不能管理其他成员。
- 使用 `/factory status` 查看节点 UUID、运行状态、远端应力与协作者数量；`/factory inventory` 随时打开手动库存界面。`/factory return` 和旧别名 `/factory_return` 均可返回。
- 使用 `/factory worlds` 查看并点击操作自己创建的机器世界；也可使用 `/factory enter <节点UUID>` 与 `/factory note <节点UUID> <备注>` 命令。手动删除命令会先要求确认。
- 服务端配置文件为 `config/integrated_factory-server.toml`：`maxStructureBlocks` 限制连通结构规模，`maxRemoteStress` 限制单节点可运行的远端负载（0 表示不限制），`roomFlight` 控制房间内飞行，`maxForceLoadedChunks` 控制强加载区块总额度（2.0.0 默认 256，0 表示关闭）。修改后重启服务器生效。

## 尚未完成 / 已知限制

- 机器空间强加载受 `maxForceLoadedChunks` 总额度限制；额度用尽的房间会在无人观察时卸载并暂停加工。主维度核心区块未加载时，远端应力容量会关闭。
- 应力桥接依赖 Create 6.0.10 内部动力网络 API；本次修复了日志中的空网络崩溃，但仍需在目标整合包中验证真实应力结算与过载反馈。
- 输入/输出端口和拓展接口仍使用占位贴图；集成核心采用 Create 离合器几何与铁块纹理，应力端口采用 Create 创造马达机身和传动轴动画。
- 协作者命令目前要求目标玩家在线；旧存档中原有房间可能跨多个区块，会按其实际占用区块消耗强加载额度。
