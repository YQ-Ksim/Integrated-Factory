# Integrated Factory 详尽说明书

适用版本：Integrated Factory 2.5.1  
目标环境：Minecraft Java 1.21.1、NeoForge 21.1.x、Create 6.0.10。

## 1. 设计概念

Integrated Factory 将一套 Create 工厂表示为一个机器节点。节点有唯一 ID、所有者、协作者、机器空间位置、输入/输出库存、结构成员、应力快照、状态与备注。

每个节点的机器空间在同一个技术维度 `integrated_factory:factory_room` 中占据独立区域。区域彼此隔离，房间内仍然运行 Minecraft/ Create 的真实方块实体、配方和传动逻辑。主维度承担接口、共享库存及动力负载结算。节点数据、库存和返回位置保存在服务端世界存档数据中。

## 2. 内容清单

### 2.0 2.4.6 至 2.5.1 更新总览

这一阶段的重点是把“能运行的机器节点”补齐为可长期维护的 Create 附属系统：

- 简单集成单元完成四向水平朝向和输入/输出面映射；核心与简单单元继续使用左右贯通的 Create 风格动力轴，轴体截面改用官方 `axis` / `axis_top` 贴图并保留半像素延伸。
- 新增基石方块，使用平滑石头外观复制基岩属性，并从数据标签和代码两层阻止凋灵、蓝色凋灵头、末影龙等实体破坏机器空间地面。
- 多方块结构增加多核心唯一性、结构数量上限、孤立接口判断、端口/拓展接口合并保护，以及活塞、轴承、底盘等 Create 动态结构移动保护。
- 节点管理扩展为 `/factory worlds` 聊天管理行、所有者/协作者权限、备注、进入、删除和重绑定；潜行交互可以在结构统计或库存界面旁显示对应节点管理行。
- 蓝图大炮边界检查接入 Create 的放置前流程。机器空间外的方块和实体目标会在容器抽取材料前跳过，房间内仍保留 Create 原有打印机制。
- 删除节点会释放强加载、清理已加载主世界结构的旧节点 UUID，并将原核心转为普通掉落物；删除前遗留的绑定核心可以作为新核心重新放置，放置冲突不会再通过事后移除造成物品吞失。

### 2.1 集成单元（多方块核心）

- 是大型集成结构的核心，一个有效结构必须且只能包含一个集成单元。
- 放置时正面朝向玩家；其左右两面是 Create 动力轴连接面，另外四面不传递动力。
- 通过扳手可水平转向；空手普通右键进入对应机器空间，蹲下空手右键显示结构统计。
- 方块的旋转轴接入 Create 网络，所登记的远端应力负载映射为本地应力影响。模型轴方向随核心实际动力轴对齐并动画旋转。
- 挖掘掉落会保留节点 ID 和必要的绑定数据；绑定核心物品有附魔光效。重新放置可恢复节点关联。

### 2.2 简单集成单元

- 是不参与多方块结构扫描的独立节点；功能上提供核心、输入库存和输出库存。
- 正面为输入面，背面为输出面，左右面贯穿 Create 动力轴；上下两面不提供物品自动化能力。
- 前面、后面、左右面、上下分别使用简单单元专用纹理；外观沿用 Create 离合器/齿轮箱的结构，左右轴使用与核心相同的旋转轴动画。
- 空手普通右键进入房间；蹲下空手右键打开同时显示输入和输出库存的界面；扳手用于转向。
- 绑定数据、掉落恢复和应力映射与多方块核心使用同一节点系统。
- 朝向状态只保存水平 `FACING`，因此可绕竖直轴在北、东、南、西四向旋转，但不会沿 X/Z 轴翻转。

### 2.3 基石

- 注册名为 `integrated_factory:cornerstone`，复制原版基岩的硬度、爆炸抗性、音效、工具要求和掉落行为。
- 资源模型使用 `minecraft:block/smooth_stone`，因此外观是平滑石头而不是基岩。
- 新机器空间的地面（包括边缘地面）使用基石；屏障侧墙仍负责阻止玩家越界。

### 2.4 拓展接口

拓展接口只负责让多方块结构延伸或分支，不储存物品、不传递动力，也不建立独立节点。六个面使用 `extension_interface.png`。可使用 Create 扳手按 Create 的交互流程拆除并掉落。

### 2.5 输入端口与输出端口

两种端口都属于所连接核心的节点。每个节点的输入库存、输出库存各 27 格；同类的多个端口访问同一个库存实例，不会因增加端口而增加格数。

| 端口 | 主维度自动化 | 机器空间自动化 | 手动界面 |
|---|---|---|---|
| 输入端口 | 允许插入输入库存，不允许提取 | 允许提取输入库存，不允许插入 | 蹲下右键只显示输入库存 |
| 输出端口 | 允许提取输出库存，不允许插入 | 允许插入输出库存，不允许提取 | 蹲下右键只显示输出库存 |

输入端口六面使用 `input_port.png`，输出端口六面使用 `output_port.png`。自动化通过 NeoForge 标准物品处理能力提供，并兼容 `IItemHandlerModifiable` 查询。手动容器界面直接操作节点库存，服务端库存是唯一权威数据。

### 2.6 应力端口

- 放置时采用 Create 定向动力方块的朝向规则，优先连接附近的传动轴；只有其朝向端面连接动力网络。可用扳手转向。
- 在机器空间中充当单向虚拟动力源，旋转速度跟随主维度核心的理论转速，不固定输出 256 RPM。
- 读取与应力端口连接的 Create 网络应力数据，并将负载登记到主维度核心所在网络。
- 远端容量依据主维度网络可用 SU 计算；节点无效、核心区块不可用、主网络无运行转速或应力超出配置限值时，远端容量关闭。
- 不把 Create 传动杆等无应力消费者误计为负载；本模组使用 Create 网络缓存和内部 API，修改 Create 版本后应重新验证兼容性。
- 应力端口模型使用本模组黄色马达机身与 Create 轴端样式；具体视觉及动力网络动画应以目标客户端整合包验证为准。

## 3. 多方块结构规则

结构扫描由服务器上的集成核心发起，以六个面为邻接关系搜索核心、拓展接口、输入端口和输出端口。扫描周期为 40 tick，默认结构上限为 128 个成员。

有效条件：

1. 连通成员不超过 `maxStructureBlocks`。
2. 连通结构中恰好有一个集成单元。
3. 端口、拓展接口只能登记到一个有效核心节点。
4. 结构变化后会重新登记成员；无核心、多个核心、超上限等情况标记为无效，不把接口随意分给其他节点。

核心放置在服务端交互阶段先计算真正的目标方块位置。若目标紧邻已有核心或已成型结构，会在扣除物品前拒绝；孤立的输入端口、输出端口和拓展接口不会单独阻止补放核心。连接两个已有核心结构的端口或拓展接口同样在放置前拒绝，并保留玩家手中物品。Create 蓝图、非玩家放置路径以及活塞、轴承、底盘等动态移动路径不会获得核心激活许可。

多核心冲突发生在强制手段或旧存档恢复时，服务端会优先保留与节点主机坐标一致的原核心；其他核心被移除并按绑定状态生成掉落物。简单集成单元不加入大型结构扫描，因此不会因为靠近大型结构而触发多核心冲突。

集成核心蹲下空手右键显示统计：输入端口数、输出端口数、拓展接口数、集成单元数及当前节点状态。若某些成员区块未加载，统计按已加载区块中实际可读取的成员显示。

## 4. 机器空间使用方式

### 4.1 房间尺寸与隔离

- 所有节点使用同一隐藏技术维度，房间的内部范围是 X/Z 各 10 格、Y 方向 10 格（楼层上方 y=65–74）。每间房间独立分配坐标并留有区块间距。
- 首次进入时生成光滑石地面和屏障侧墙；软件边界也会把玩家限制在当前节点空间内。
- 玩家破坏方块、放置方块时，服务器校验其是否在当前有权访问的房间区域。机器空间内禁止放置集成核心或简单集成单元，防止递归创建节点。
- 多名获准玩家可进入同一节点空间协作；不同节点对应不同区域。
- 真实 Create 机器仍需服务器端方块实体 tick。没有强加载票据且无人处于区域时，不保证机器继续运行。

### 4.2 进入和返回

- 主维度核心空手普通右键进入。已获准玩家也可用 `/factory enter <节点UUID>` 进入。
- 进入点由服务器在房间内查找无碰撞且无流体的位置；找不到安全站位时取消传送，避免卡进方块。
- 进入前的位置、维度、视角及飞行能力保存于玩家数据。`/factory_return` 或 `/factory return` 返回原位置，并恢复保存的飞行能力。
- `roomFlight=true` 时，在机器空间内给予飞行；关闭时不额外给予飞行权限。

### 4.4 蓝图大炮边界

机器空间中的蓝图大炮仍然可以从相邻容器抽取材料并打印 Create 蓝图，但目标必须位于当前节点的 10×10×10 建造范围（x/z 各 10 格，y=65–74）。边界检查同时接入 `SchematicPrinter.shouldPlaceCurrent` 和蓝图炮自身的 `shouldPlace`，因此方块目标和实体目标都会在 Create 检查材料、从 `IItemHandler` 抽取物品之前被跳过。越界目标不会生成方块，也不会把材料作为正常打印流程消耗。

旧存档中已经处于飞行状态的方块会在落点更新前再次检查；这只是竞态/旧数据兜底，不改变机器空间内的正常打印流程。

### 4.3 强加载

每个新建房间的 10×10 区域被放置在一个区块内。服务端配置 `maxForceLoadedChunks` 限制模组用于机器空间的总 block-ticking 区块数，默认 256，范围 0–4096。设为 0 时禁用强加载。

节点只有在有效、启用、主维度核心所在区块已加载且额度足够时才分配强加载票据；额度不足时优先保留最近访问的房间。主核心区块卸载或节点失效时，远端强加载会被回收。服务器约每 100 tick 协调一次票据，启动时也会恢复票据。

## 5. 库存与数据持久化

- 每节点 `input` 与 `output` 各 27 格，均由 `IFMachineData` 统一保存。
- 主世界端口、机器空间端口、简单单元接口和手动容器都直接操作同一份节点库存，不通过副本定时同步。
- 节点登记、库存、机器空间坐标、房间初始化状态、结构成员、所有者、协作者、备注、状态、远端应力快照、主维度理论转速快照及玩家返回位置写入 SavedData。
- 删除节点会移除节点登记和库存，因此再次删除确认前应先取出需要保留的物品。机器空间内原有方块会保留在该坐标，但节点空间被标记为退役，不会分配给新节点。主世界结构中已经加载的端口和拓展接口会同步清除旧节点 UUID，避免删除后补核心仍被旧绑定阻塞。
- 删除命令执行时，原主机核心会转换为不带节点数据的普通核心掉落物。若玩家手中仍有删除前掉落的附魔绑定核心，放置时会识别节点已删除并清除旧绑定，作为新节点核心使用；放置冲突只在放置前判定，不会先扣物品再把方块移除。
- 核心掉落会携带绑定节点 ID。若核心遗失，所有者可在机器空间中手持一个核心物品蹲下右键，取得此空间的一次性重绑定令牌；随后将物品带回主维度放置以接管该机器空间及其库存。该操作不在机器空间实际放置方块。

## 6. 所有权和协作权限

- 玩家首次放置集成核心或简单单元时成为节点所有者。
- 所有者与协作者可以访问节点房间、节点库存和状态；只有所有者可以管理协作者、修改备注、删除节点或执行机器空间内核心重绑定。
- `/factory allow <玩家>` 和 `/factory deny <玩家>` 在当前机器空间内运行，仅接受在线玩家名；协作者集合按 UUID 保存。
- 若旧数据节点没有所有者，首次有权访问者可能成为所有者。

## 8. 状态解释

状态会随结构和 Create 网络同步变化，常见值包括：

| 状态 | 含义 |
|---|---|
| `unlinked` | 节点刚建立，机器结构/应力端口尚未完成关联或初始化。 |
| `ready` | 结构有效，未检测到当前结构或应力限值错误。 |
| `invalid_structure` | 结构超出成员上限或连通组件不符合单核心规则。 |
| `rebuilding` | 核心恢复或重绑定后，结构正在重新识别。 |
| `core_removed` | 原主维度核心已移除；节点保留但停止正常运行。 |
| `awaiting_rebind` | 所有者已请求用核心物品接管该机器空间，等待物品重新放置。 |
| `stress_limit` | 机器空间的远端应力超过 `maxRemoteStress`，远端应力容量关闭。 |

具体状态转换依赖方块实体加载和 Create 网络重算，不应仅凭单次聊天输出判断整套工厂的所有机器都处于工作状态。

世界重载时，节点中的运行时远端应力/转速快照会先清空，核心和应力端口重新加入 Create 网络后再读取当前成员计算应力与容量，并触发一次应力/容量总量重算，以消除旧存档快照和 `unloaded` 缓存造成的假过载。正常运行中仍主要按负载变化或网络重建更新。

机器空间区块单独重新加载时，应力端口也会执行相同的恢复流程：先清除本节点旧运行时负载，等待 Create 成员恢复，再发布新的远端应力。

由于机器房间完整限制在单个区块内，恢复时还会清理 Create 网络中记录的未加载成员应力、容量和成员数量，再按当前实际成员计算，防止已不存在或尚未恢复的机器继续贡献负载。

主世界核心和机器空间应力端口可能以不同顺序重新加载。模组会暂存本节点核心恢复前的旧应力，在任一方先入网时只移除该核心的残余贡献，再让另一方加入网络，避免把主世界中其他 Create 设备的未加载应力误删。

恢复时还会显式同步 Create 网络成员，即使网络总应力和容量数值没有改变，也会刷新方块实体从存档中恢复的过载标志。

如果机器空间成员延迟加载导致 Create 在恢复期间替换远端网络对象，应力端口会对每个新网络对象重新清理未加载成员快照并同步。

远端应力最终只统计当前网络中仍对应实际方块实体的成员，不把 Create 保存的未加载成员快照桥接到主世界。

## 9. 服务端配置

配置文件为 `config/integrated_factory-server.toml`，分类为 `[factory]`。

| 项 | 默认值 | 范围/含义 |
|---|---:|---|
| `maxStructureBlocks` | 128 | 每个集成核心允许的最大连通结构成员数，范围 1–4096。 |
| `maxRemoteStress` | 0 | 单节点远端 Create 应力上限，范围 0–1e12；0 表示不限制。 |
| `roomFlight` | true | 进入机器空间后是否给予飞行权限。 |
| `maxForceLoadedChunks` | 256 | 模组用于机器空间的总强加载区块额度，范围 0–4096；0 表示禁用。 |

## 10. 模型与资源

本模组提供集成核心、简单集成单元、拓展接口、输入端口、输出端口和应力端口。简单单元前后/左右/上下使用独立纹理；拓展接口与输入/输出端口使用对应六面纹理。集成核心和简单单元的动态传动轴由 Flywheel partial 绘制，物品图标使用静态模型表现轴体。

可编辑模型、元素位置和导入/应用方法见项目 `blockbench/README.md`。Blockbench 源模型不会自动同步至正式资源；修改后需复制回 `src/main/resources/assets/integrated_factory/models/` 并重新打包。

## 11. 安装与已知限制

1. 安装 Minecraft Java 1.21.1、兼容的 NeoForge 21.1.x、Create 6.0.10 及其依赖。
2. 将 `integrated_factory-2.5.1.jar` 放入实例 `mods` 文件夹。
3. 服务器首次启动后可在 `config/integrated_factory-server.toml` 调整服务端配置。
